# 第 8 步：客人自己查訂單

**日期**：2026-08-18

---

## 這一步在做什麼

客人下完單，過兩天會想知道「**我的茶寄了沒**」。
現在他只能打電話問您。這一步讓他自己查。

網址：**https://shinyumin.vercel.app/zh/orders**
（頁尾也有一個「**查我的訂單**」的連結，客人隔幾天從首頁進來也找得到）

客人填兩樣東西：

| | |
|---|---|
| **訂單編號** | `YM-` 開頭那一串，在完成頁上 |
| **電話後四碼** | 下單時填的那支電話的最後四個數字 |

兩樣都對，就會看到：目前狀態（待付款／已付款準備出貨／已出貨／已完成／已取消）、
下單時間、買了什麼、金額，以及一句「要改地址或取消請來電」加上電話。

---

## 為什麼不是做「會員登入」

您本來說要做會員登入，我先做了這個，理由是：

**會員系統需要寄信，而寄信正是目前卡住的東西。**

- 註冊要驗證信箱
- **忘記密碼要寄重設信** ← 這個一定會發生

沒有網域就沒辦法寄信，客人忘記密碼**連您也救不回來**，
那會變成您每天要接的電話 —— 比不做會員還糟。

而且客人真正想要的通常不是一個帳號，是「查我的茶寄了沒」。
這一版**不用註冊、不用記密碼、不用收信**，就把那件事做完了。

> 等 `yumintea.com.tw` 付好、Resend 驗證完成，隨時可以再往上加
> 「email 驗證碼登入」（輸入信箱 → 收六位數字 → 登入，不用記密碼）。
> 現在做的這一頁不會白做，到時候是多一個入口，不是打掉重來。

## 安全上怎麼設計的（這一段是重點）

**訂單編號是流水號，任何人都猜得到**（`YM-20260818-0001`、`0002`…）。
所以只靠編號就能查，等於把所有客人的訂單攤在網路上。

三道設計：

### 一、要兩樣同時對

編號 **加上** 電話後四碼。四碼有一萬種組合。

### 二、猜錯與查無此單，回的東西一模一樣

如果「查無此單」與「電話不對」回不同的訊息，
對方可以用「這個編號存在」這件事本身推算出您有多少訂單。
所以兩種情況回的都是同一句「查不到這張訂單」。

### 三、十五分鐘只能查五次

一萬種組合對程式來說不算多 —— **是限流讓它變得不值得試**。
一天最多試四百多次，離一萬還很遠，而正常客人查自己的訂單不會打錯五次。

### 另外：這一頁看得到的東西比後台少

**沒有地址、沒有 email、沒有完整電話。** 客人自己知道那些，
而萬一真的有人猜中四碼，這裡少放一樣就少洩漏一樣。
要核對地址請客人來電。

查詢也**不吃網址參數** —— 沒辦法把網址複製給別人讓別人看到您的訂單。

## 我測過什麼

在本機建了一張真的訂單（電話 `0912-345-678`），然後：

| 測試 | 結果 |
|---|---|
| 對的後四碼 `5678` | ✅ 200，查得到 |
| 錯的後四碼 `1234` | ✅ 404 |
| 不存在的編號 | ✅ 404（跟上面**一模一樣**） |
| 亂填的編號 | ✅ 404 |
| 第五次查詢 | ✅ 還可以 |
| 第六次查詢 | ✅ 429，被擋下 |
| 訂單編號打小寫 | ✅ 自動轉大寫，查得到 |
| 電話存成 `0912-345-678`、客人只打數字 | ✅ 比對前會抽掉所有非數字 |
| 回傳的內容 | ✅ 沒有地址、電話、email、姓名 |

測試訂單已從資料庫刪除。
