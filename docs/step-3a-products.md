# 第 3 步（前半）：把商品接上資料庫

**日期**：2026-08-17

---

## 這一步做了什麼

在這之前，網站上的「紅玉紅茶 150g NT$650」是**寫死在程式裡的文字**。
現在它是**從資料庫讀出來的**。

差別在哪裡：等第 6 步的後台做好，您在手機上把價格改成 680，
網站上最慢一分鐘後就會變成 680 —— 不需要找工程師改程式。

具體改了兩頁：

| 頁面 | 現在的內容從哪來 |
|---|---|
| **首頁**的分類（紅茶／烏龍／綠茶） | 資料庫 |
| **首頁**主力茶款的名稱、風味、規格、價格 | 資料庫 |
| **茶品**頁 | 資料庫（整頁） |

---

## 茶品頁

每一款茶佔一整段，圖與文字左右交錯排列，底下用細線列出所有包裝規格與價格。
沿用全站的編輯式排版，不做成常見的商品卡片格。

售罄的規格會顯示「售罄」並在價格上劃線 —— **看得到，但買不了**。
已下架的則完全不會出現（資料庫的門禁擋掉，程式再擋一次，兩道保險）。

---

## 為什麼是「最慢一分鐘」

網站不是每次有人來看就去問一次資料庫 —— 那樣既慢又浪費。
作法是：**把做好的頁面存起來直接送給訪客，每 60 秒才回頭跟資料庫確認一次有沒有變。**

對您的意義：後台改完價格，最多等一分鐘網站就會更新，不用擔心改了沒生效。

---

## 鑰匙還沒填，所以現在看到的是備援內容

`.env.local` 裡的兩把鑰匙還沒填（那要在電腦上做，見
[`docs/step-1-supabase.md`](step-1-supabase.md) 的第 ④ 步）。

在鑰匙填好之前：

- **首頁**會顯示寫在翻譯檔裡的備援內容（就是您現在看到的樣子），版面完整不開天窗
- **茶品頁**會顯示「商品正在整理中，很快就會上架」

鑰匙一填好，兩頁都會自動換成資料庫裡的真實資料，不需要再改任何程式。

> 這是刻意設計的：資料庫連不上時**不讓網站壞掉**，而是退回一個好看的替代畫面。
> 日後萬一 Supabase 暫時故障，客人看到的也不會是錯誤頁。

## 檔案

| 檔案 | 作用 |
|---|---|
| `src/lib/supabase.ts` | 與資料庫的連線。鑰匙沒填時回傳「沒有連線」而不是壞掉 |
| `src/lib/products.ts` | 讀商品的程式。負責挑語言（中文站給中文欄位）、排序、過濾下架品 |
| `src/app/[locale]/teas/page.tsx` | 茶品頁，整頁改為讀資料庫 |
| `src/app/[locale]/page.tsx` | 首頁的分類與主力茶款改為讀資料庫 |

---

## 已驗證 / 未驗證

**已驗證**：`npm run lint`、`npm run build` 通過；鑰匙未填時首頁與茶品頁都正常顯示
備援內容，瀏覽器主控台無錯誤，手機寬度無水平溢出。

**未驗證**：與真實資料庫的連線。**這要等 `.env.local` 填好之後才能測**。
填好後請執行下面這行，會實際去讀資料庫並印出結果：

```bash
npm run check:supabase
```
