# 第 5 步：LINE 訂單通知

**日期**：2026-08-17

---

## 這一步在做什麼

第 4a 步做完之後，客人下的單會進資料庫 —— 但**沒有人會知道**。
您得自己去 Supabase 看才發現有訂單。

這一步就是讓**訂單一成立，LINE 群組馬上跳出一則通知**。

> **這則推播是要給媽媽看的。** 她是實際在處理訂單、接電話、出貨的人，
> 需要第一時間知道有新訂單進來，所以群組要以「她收得到」為準來建。
>
> **您自己不必靠這個。** 您要的是 Claude Cowork 主動通知，
> 加上第 6 步那個可以在手機上點進去看訂單的網頁後台 ——
> 那兩件事還在後面，這一步不影響它們。

訊息長這樣（這是我實際跑出來的，不是想像的）：

```
🍵 新訂單
YM-20260817-0001

紅玉紅茶
　四兩・150g 鐵罐 × 2　NT$ 1,200
台灣山茶
　二兩・75g 鐵罐 × 1　NT$ 350

──────────
商品　NT$ 1,550
運費　NT$ 130（郵局）
合計　NT$ 1,680
──────────

付款　匯款
　　　⚠️ 兩個工作天內打電話給客人，告知匯款帳號

收件　王小明
電話　0912345678
地址　555 南投縣魚池鄉大雁村山楂腳巷 10-20 號
信箱　ming@example.com
```

選貨到付款的話，那一行會變成「代收手續費另計，記得跟客人講」。
滿 $2,000 免運的訂單，運費那一行會直接寫「免運」。

**這則訊息是純樣板，不經過 AI。** 它要的是快、數字正確、必定送達 ——
這裡沒有任何需要動腦的事，多接一個 AI 只會多一個會壞掉的環節。

## 請您操作（大約 15 分鐘，全部可以用手機做）

> ⚠️ **從頭到尾都在「御茗內部通知」這個新帳號上操作。**
> **絕對不要動您現有的客服官方帳號** —— 那個帳號一旦切成機器人模式，
> 真人聊天功能會失效，客人傳訊息就沒有人回得了。

### ⚠️ 最重要的前提：LINE 有【兩個】後台，而且兩邊都有「Messaging API」

**這是本步驟唯一真正的坑，業主 2026-08-17 就是卡在這裡。**
兩個網站都有一個叫 Messaging API 的地方，但東西不在同一邊：

| 網站 | 這裡有什麼 | 這裡沒有什麼 |
|---|---|---|
| **官方帳號管理頁面**<br>`manager.line.biz`<br>（中文介面） | Channel ID、**Channel secret**、**Webhook 網址**、回應設定 | **沒有 access token，永遠不會有** |
| **LINE Developers Console**<br>`developers.line.biz`<br>（英文介面） | **Channel access token**（Messaging API 分頁最底下，要按 Issue） | — |

在中文那個後台把整頁翻爛也找不到 access token，**不是漏看，是它真的不在那邊**。
中文後台最底下那句「您可由 LINE Developers Console 進行其他設定」裡的
藍色連結，就是通往另一個網站的門。

### ① 拿兩把鑰匙

**Channel secret** 在中文後台（`manager.line.biz`）→ 設定 → **Messaging API**，
按旁邊的「複製」。那一頁最上面如果寫「狀態：**使用中**」，
代表 Messaging API 已經開通了。

（如果狀態不是使用中，就先在那一頁按「啟用 Messaging API」，選一個 Provider。）

**Channel access token** 在 [LINE Developers](https://developers.line.biz/console/)，
進入同一個 channel。

上面那排分頁（在手機上要**左右滑**才看得到全部）點 **Messaging API**，
**一路捲到最底下**，最後一個區塊是 **Channel access token**，
第一次要自己按 **Issue** 才會產生。

兩個都是很長一串英數字。**先不要貼進我們的對話** —— 等一下直接貼進 Vercel。

> ⚠️ **Channel ID 不是我們要的東西**，雖然它跟 Channel secret 排在一起。

### ② 把三個設定填進 Vercel

到 [Vercel 的專案設定](https://vercel.com/) → 您的專案 →
**Settings** → **Environment Variables**，加兩個（第三個等一下才會有）：

| Name | Value |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | 剛剛的 Channel access token |
| `LINE_CHANNEL_SECRET` | 剛剛的 Channel secret |

加完到 **Deployments** 分頁，最上面那一筆按右邊的 **⋯** → **Redeploy**。
等 1–2 分鐘。

> 為什麼要重新部署：環境變數是在網站「啟動」的時候讀進去的，
> 光是填進去、不重開，網站還是用舊的設定在跑。

### ③ 打開 Webhook、關掉自動回應

到 [LINE 官方帳號管理頁面](https://manager.line.biz/) →
「御茗內部通知」→ 右上角 **設定** → **回應設定**：

| 項目 | 要設成 |
|---|---|
| 聊天 | **關閉** |
| Webhook | **開啟** ✅ |
| 自動回應訊息 | **關閉** ✅ |

**自動回應訊息一定要關掉。** 它開著的話，LINE 會自己先回一句罐頭訊息、
然後把事件攔下來不轉給我們，通知就永遠不會送出。這是最常見的卡關原因。

**Webhook 網址在中文後台就能填**，不必跑到 LINE Developers ——
就在剛剛拿 Channel secret 的那一頁（設定 → Messaging API），
Channel secret 底下那個空的 `https://` 欄位：

```
https://shinyumin.vercel.app/api/line/webhook
```

填完按綠色的「**儲存**」。

（LINE Developers 的 Messaging API 分頁上也有同一個欄位，
兩邊填的是同一個東西，填一邊就好。那邊多一個 **Verify** 按鈕可以測，
出現 **Success** 代表網址通得到。）

> 網域 `yumintea.com.tw` 接上去之後，這個網址要改成
> `https://yumintea.com.tw/api/line/webhook`，記得回來改。

### ④ 把機器人加進群組，拿群組 ID

**這一步是整個第 5 步最容易卡住的地方**，所以我做了一個自動的作法。

問題是這樣：要把訊息推到某個群組，程式必須知道那個群組的 ID。
但**LINE 後台沒有任何一個地方看得到群組 ID** —— 真的沒有，不是您找不到。

我的作法：**讓機器人自己把 ID 講出來。**

1. 建一個 LINE 群組（例如「御茗訂單通知」），**把媽媽拉進去**
   （她是主要要看這些通知的人），其他需要的家人也一起
2. 把「御茗內部通知」這個官方帳號**加進那個群組**
3. 在群組裡隨便打一句話，例如「哈囉」
4. 機器人會馬上回一則訊息：

   > 這個群組的 ID 是：
   >
   > Cxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   >
   > 請長按上面那一行複製，貼到 Vercel 的環境變數 LINE_GROUP_ID。

5. **長按那一行複製起來**

如果機器人沒有回話，回去檢查第 ③ 步的「自動回應訊息」有沒有真的關掉。

### ⑤ 填最後一個設定

回到 Vercel → **Settings** → **Environment Variables**，再加一個：

| Name | Value |
|---|---|
| `LINE_GROUP_ID` | 剛剛複製的那一串（`C` 開頭） |

一樣要 **Redeploy** 一次。

設定完成之後機器人就會安靜下來，不會再對群組裡的每一句話回話。
之後想再看一次群組 ID，在群組裡打「**ID**」它就會再回一次。

### ⑥ 測試

到 https://shinyumin.vercel.app 隨便下一張測試訂單，
群組應該在幾秒內跳出通知。

測試訂單記得到 Supabase 的 Table Editor 刪掉
（先刪 `order_items` 再刪 `orders`）。

## 我在您電腦上也放了一支健檢程式

如果通知沒出現、想知道是哪一段壞了，在專案資料夾執行：

```bash
npm run check:line
```

它會實際推一則「這是一則測試訊息」到群組，並且在失敗時告訴您
是鑰匙錯了、群組 ID 錯了，還是額度用完了。

要跑這支程式，您電腦上的 `.env.local` 也要補上那三行
（照 `.env.example` 的格式，值跟 Vercel 上填的一樣）。

## 三件您應該知道的事

### 一、免費方案每個月 200 則

LINE Messaging API 的免費額度是**每月 200 則推播**。
一天 6 張訂單就會用完。真的做起來之後可能要升級方案 ——
不過那是「生意好」的煩惱，現在不用管。

順帶一提：**機器人回覆訊息（例如回貼群組 ID）不算在額度裡**，
只有主動推播才算。

### 二、通知失敗不會影響訂單

訂單是先寫進資料庫、再推 LINE 的，而且推播是在回覆客人**之後**才跑。
所以就算 LINE 掛掉、鑰匙過期、額度用完，**客人的訂單一樣會成立**，
只是您不會收到提醒。訂單永遠都在 Supabase 裡。

反過來說：**LINE 沒響不等於沒有訂單。** 第 6 步的手機後台做好之後，
您會有一個地方可以完整地看所有訂單，不必依賴 LINE。

### 三、這則訊息裡有客人的個資

通知裡有客人的姓名、電話、地址 —— 因為您需要這些才能打電話、才能出貨。

所以**這個群組請只放自己人**，不要把它變成半公開的群。
如果您覺得地址不該出現在 LINE 上，跟我說一聲，拿掉那一行只要改一個字。

## 一個安全上的細節

Webhook 的網址是公開的，任何人都打得到。
所以每一筆進來的請求，我都會用 Channel secret **重新算一次簽章**，
對不起來就直接擋掉（回 401）。

我實際測過：沒有簽章、假簽章、內容被竄改，三種都擋得下來。
沒有這道檢查的話，路人可以假裝成 LINE 對這支程式亂送東西。
