# 第 6a 步：手機後台（看訂單、標記出貨）

**日期**：2026-08-17

---

## 這一步在做什麼

您說的那個「**放在手機裡面、可以直接點進去看訂單**」的後台，做好了。

第 6 步一共要做四件事，我拆成兩半，這是前半：

| | 內容 | 狀態 |
|---|---|---|
| **第 6a 步** | 密碼登入、看訂單、標記已付款／已出貨／已完成、取消訂單 | ✅ 這一份 |
| 第 6b 步 | 改價、切售罄 | 下一步 |

先做看訂單，是因為那是**每天都會用到的**；改價是偶爾才做的事。

網址是 **https://shinyumin.vercel.app/admin** —— 建議加到手機主畫面，
用起來就跟一個 app 一樣。

---

## ⚠️ 需要您做一件事（約 3 分鐘）

**設一組後台密碼。** 沒設定的話後台會直接拒絕進入（不是放行，這是刻意的）。

1. 到 [Vercel](https://vercel.com/) → 您的專案 → **Settings** → **Environment Variables**
2. 加一個：

   | Name | Value |
   |---|---|
   | `ADMIN_PASSWORD` | 您自己想的密碼 |

3. 到 **Deployments** → 最上面那筆的 **⋯** → **Redeploy**

密碼**請設長一點**，例如四個不相干的中文詞連起來，或十二個以上的英數字。
這一組密碼等於整間店的訂單資料 —— 裡面有每一位客人的姓名、電話、地址。

> 密碼請直接貼在 Vercel 的欄位裡，**不要貼進我們的對話**。

## 打開之後長什麼樣子

### 訂單列表

最上面一排是「**還有幾張要處理**」：待付款、已付款、已出貨各幾張。

下面是所有訂單，**新的排在最上面**。每一列有：客人姓名、金額、狀態、
付款方式、時間、訂單編號。**整列都可以點**，手機上不用瞄準小連結。

還沒出貨的訂單（待付款、已付款）狀態會用**品牌赭紅**標出來 ——
那些是還要做事的。已完成的就是灰的，不會來吵您。

### 一張訂單的內容

點進去會看到：

- **品項**（買了什麼、什麼包裝、幾件、多少錢）
- **金額**（商品／運費／合計，以及付款方式）
- **收件資料** —— **電話是可以直接點的**，點一下手機就撥出去。
  匯款的訂單一定要打這通電話告知帳號，所以我把它做成最好按的樣子。
- 備註、發票（有填才會出現）

### 處理

**下一步永遠只給一個按鈕**：

| 現在的狀態 | 按鈕 |
|---|---|
| 待付款 | 標記已付款 |
| 已付款 | 標記已出貨 |
| 已出貨 | 標記已完成 |

全部狀態都列出來看起來比較自由，但您站在店裡單手操作時，**選項越少越不會按錯**。

下面另外有兩個做得比較不顯眼的連結：**改回待付款**（按錯了可以退回去）
與**取消這張訂單**。刻意做小，避免手滑。

按「標記已付款」的時候，付款狀態會**自動**跟著變成已付款 ——
您不需要記得按兩次。

## 您可以怎麼驗證

等您設好密碼、Redeploy 完之後：

1. 手機打開 https://shinyumin.vercel.app/admin
2. 先**故意打錯密碼** → 應該顯示「密碼不對，再試一次。」
3. 打對 → 進到訂單列表
4. 到前台下一張測試訂單，回後台重新整理，應該看得到
5. 點進去，按「標記已付款」，狀態應該變成「已付款」，
   按鈕變成「標記已出貨」
6. 按右上角**登出**，再直接打 `/admin` → 應該被踢回登入頁

測試訂單可以在 Supabase 的 Table Editor 刪掉。

我在本機已經把這一整條路實際跑過一遍了（打錯密碼、登入、看列表、
點進訂單、標記已付款、確認資料庫真的變了、登出之後進不去）。

## 幾個您應該知道的設計決定

### 一、後台長得跟前台不一樣，這是故意的

前台是型錄：大量留白、巨大標題、不對稱的版面。
**後台是工具**：字大、按鈕大、一眼看得懂。您可能站在店裡、手上還拿著茶葉。

顏色還是用同一份設定檔，所以仍然是御茗的色，只是版面樸素得多。

後台也**不載入標題那套楷書字型** —— 那套中文字型接近 1MB，
為了一個每天要開很多次的工具頁下載它並不划算。

### 二、密碼不會存在您的手機裡

登入成功之後，放進您手機的不是密碼，而是一張「**通行證**」：
上面只有到期時間，加上一段用密碼算出來的簽章。

就算有人拿到那張通行證，也**回推不出您的密碼**；
想偷改上面的到期時間，簽章就對不起來。通行證**14 天**到期，
所以平常不會一直要您重登。

**您改密碼之後，所有已經登入的裝置會一起被登出** —— 這是刻意的。
萬一手機掉了，改密碼就等於把所有裝置踢掉。

### 三、密碼有次數限制

同一個地方**十分鐘內最多試 8 次**，超過就先擋著。

只有一組密碼，不擋的話寫個小程式一秒試幾百次，遲早會被試出來。

### 四、每一個動作都自己檢查一次

不只是「頁面有擋」，**按鈕背後的動作也各自檢查有沒有登入**。
因為那些動作本身也是一個網址，沒登入的人可以直接對它送請求 ——
只擋頁面是擋不住的。

## 檔案放在哪裡

| 檔案 | 是什麼 |
|---|---|
| `src/lib/admin-auth.ts` | 密碼比對與通行證 |

| `src/app/admin/orders/[id]/page.tsx` | 一張訂單的內容與處理按鈕 |
| `src/app/admin/actions.ts` | 登入、登出、改狀態 |
| `src/proxy.ts` | 加了一行，讓 `/admin` 不要被語言分流導走 |
