## 購物車：只記規格與數量，不記價格

這是整個專案最重要的一條安全規則，這一步正式落實。

購物車存在**客人自己的瀏覽器**裡。稍微懂技術的人可以打開開發者工具，
把裡面的內容改成任何東西。如果價格存在那裡，等於把訂價權交給客人 ——
有人把 650 改成 1，網站就照 1 元算。

所以購物車裡**只有兩個東西：規格 ID 與數量**。
實際存進瀏覽器的長相就是這樣：

```json
{ "lines": [ { "variantId": "…", "quantity": 2 } ] }
```

價格永遠是**即時從資料庫查出來顯示**的。

這順帶解決了另一個問題：客人把茶放在購物車裡好幾天，期間您調過價，
他回來看到的會是**新價格**，不是舊的。

> 第 4 步結帳時，伺服器還會再查一次資料庫重新計算總額 ——
> 前端送來的任何金額一律不採信。

## 幾個刻意的設計

**售罄的包裝看得到但選不了。** 客人會知道「有這個品項，只是暫時沒貨」，
比讓它直接消失更清楚，也保留了日後補貨的期待。價格會劃線。

**已下架的完全不出現。** 資料庫的門禁擋一次、程式再擋一次，兩道保險。

**購物車裡的規格如果之後被下架了**，那一列會顯示「這個規格已經下架，請先移除」，
並且**不計入合計** —— 不會發生「結帳金額對不上」的情況。

**按鈕不是按鈕。** 沿用全站語彙：包裝用細線方框、加入購物車是文字加箭頭。

## 已驗證 / 未驗證

**已驗證**（在瀏覽器實測）：

- 購物車存進瀏覽器的內容**確認只有規格 ID 與數量，沒有價格**
- 數量增減、移除、清空後顯示空購物車，選單列件數同步更新
- 購物車裡放一個資料庫查不到的規格 → 顯示「已下架請移除」且不計入合計，畫面不崩
- 品牌故事頁四段標題與版面正確，手機寬度無水平溢出
- `npm run lint`、`npm run build` 通過；重新載入後主控台無錯誤

**未驗證**：實際加入一款真商品。這需要 `.env.local` 的鑰匙填好、
網站讀得到資料庫裡的紅玉之後才能做。**商品詳情頁在資料庫接上之前會是 404**
（因為查不到那款茶），這是正常的。
