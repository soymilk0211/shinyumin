# 茶湯轉盤與標題斷行

**日期**：2026-08-17

---

## 1. 標題改成「日月潭紅茶」，而且不會斷錯行

原本是「日月潭紅玉」，而且在手機上會斷成「日月」／「潭紅玉」，
「潭」孤零零掉到下一行。

現在標題的斷行是**寫死的**，不交給瀏覽器決定：

```
日月潭
紅茶
```

翻譯檔裡存的是兩行文字（`heroTitleLines`），不是一個句子，
所以任何螢幕寬度下都不會斷錯。英文站同樣處理：`Sun Moon Lake` ／ `Black Tea`。

---

## 2. 茶湯轉盤

首頁右下角一個俯視茶湯的圓，約三分之一裁切在畫面外，隨捲動連續旋轉，
捲到不同段落時茶湯顏色柔和換過去。

### 三個關鍵作法

**旋轉不用 JavaScript。** 用 CSS 的 scroll-driven animation
（`animation-timeline: scroll(root block)`），由瀏覽器自己處理。
如果改用 JavaScript 監聽捲動再去改角度，手機上會頓。

不支援這項功能的舊瀏覽器會**安靜地顯示靜態的圓**，不會出錯
（用 `@supports` 包起來）。

**換色只改透明度。** 三張圖從頭到尾都疊在那裡，換色是讓一張淡入、其他淡出，
淡入時間 900ms。**沒有換圖檔、沒有把圖藏起來** —— 那樣會讓正在跑的旋轉斷掉。

**旋轉套在外層容器，圖片疊在內層。** 同上，會轉的那一層本身不能被動到。

### 顏色對應哪一段

判斷「現在捲到哪一段」用的是 IntersectionObserver，不是監聽捲動事件 ——
瀏覽器只在段落進出畫面的那一瞬間通知一次，捲動過程中完全不做事。

段落上掛一個 `data-tea-tone` 屬性就會被自動偵測到。目前首頁的分配是：

| 段落 | 茶湯 |
|---|---|
| 開場（日月潭紅茶） | 綠 |
| 五道工序 | 烏龍 |
| 紅玉 | 紅 |
| 分類 | 紅 |

> **這裡跟原本的規格有一點出入，要說明一下。**
> 規格寫的是「綠茶區 → 綠、烏龍區 → 烏龍、紅茶區 → 紅」，
> 但**目前首頁並沒有這三個分區** —— 分類是三格並排在同一段裡。
>
> 所以我先照製茶的順序分配：新葉（綠）→ 發酵中（烏龍）→ 成茶（紅）。
> 日後若首頁改成一個分類一個區塊，只要把 `data-tea-tone` 屬性搬過去，
> 轉盤就會自動跟著換色，不需要改轉盤的程式。

### 規格逐項確認

| 要求 | 實作 |
|---|---|
| `pointer-events: none` | ✅ 已實測：點擊會穿過去打到底下的元素 |
| z-index 低於浮動 UI | ✅ 轉盤 `z-index: 10`，選單列 `z-index: 50` |
| `prefers-reduced-motion` 停止旋轉 | ✅ `animation: none`，只留靜態圓 |
| 手機縮小約 40% | ✅ 電腦 460px，手機 173px（約螢幕寬的 46%） |
| 深淺色都協調 | ✅ 深色模式降到 55% 透明度並降低飽和度 |
| 圖檔不存在不崩潰 | ✅ 每一層底下鋪對應的顏色，沒圖就是純色圓 |

## 有一件事我沒辦法自己驗

**旋轉是否平順、換色是否柔和，我沒辦法在這裡確認。**

我用來檢查網頁的瀏覽器分頁是背景執行的（`visibilityState: hidden`），
瀏覽器在這種狀態下**完全不繪製畫面**，因此捲動動畫、CSS 過場、
段落進場偵測全都不會執行 —— 量到的角度永遠是 0 度。
這是量測環境的限制，不是程式的問題。

**可以確認的**：元素存在、位置與尺寸正確、點擊穿透、z-index 正確、
三層結構與 900ms 淡入設定正確、瀏覽器支援 scroll-driven animation
（`CSS.supports` 回報 true）、動畫已套用 `scroll(root)` 時間軸。

**要請您用真的螢幕看的**：捲動時圓有沒有平順轉、跨段落時顏色有沒有柔和過渡。
