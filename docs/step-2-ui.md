**日期**：2026-08-17

## 這一步做了什麼

第 0 步打地基、第 1 步裝檔案櫃，**這一步是把牆立起來、決定整間店長什麼樣子**。

現在網站已經看得出是一個真正的網站了：有上方選單、有頁尾、有配色、
手機和電腦都排得好看。**但商品還是假的** —— 所有照片都是佔位符，
所有茶名都是寫死的文字。第 3 步才會接上資料庫裡真正的商品。

## 您可以怎麼看

在專案資料夾執行：

```bash
npm run dev
```

然後用瀏覽器打開 http://localhost:3000

**建議您試這幾件事**：

1. **右上角的月亮／太陽按鈕** —— 深色與淺色模式互換。
   您選的模式會被記住，下次再打開還是同一個。
2. **右上角的「中文 / EN」** —— 中英文切換。
   注意它會**停在原本那一頁**，不會把您丟回首頁。
3. **把瀏覽器視窗拉窄**（或直接用手機看） ——
   選單會收成右上角的三條線按鈕，版面整個重排。
4. **點選單上的「茶品」「品牌故事」「購物車」** ——
   這三頁還沒做，但不是空白或錯誤畫面，而是一個寫著「準備中」的暫時版面。
5. **在網址後面亂打幾個字**（例如 `localhost:3000/zh/abcdefg`）——
   會看到中英並陳的 404 頁，而且選單頁尾都還在，可以直接走回去。

## 配色：為什麼是冷色配赭紅

您原本的規格寫的是紫／藍冷色系，但名片與商標實際上是溫暖的赭紅茶色。
兩者直接衝突。

我的作法是：**背景維持清冷極簡（淺色是薄霧藍、深色是午夜紫），
但所有會吸引目光的地方 —— 按鈕、連結、強調字 —— 一律用品牌赭紅。**

這樣網站保有藝廊般的安靜留白，同時您把名片遞給客人時，
客人會認得出是同一個品牌。

**所有顏色都集中在一個檔案**：[`src/app/theme.css`](../src/app/theme.css)

日後商標定稿、想把赭紅調深或調淺，只要改那個檔案裡的色碼，全站會一起變，
不需要一頁一頁找。深色模式的赭紅刻意調得比淺色模式亮一點 ——
同一個顏色放在深色背景上會顯得糊，這是必要的補償。

## 幾個看不見但重要的細節

### 信箱防爬蟲

網路上有大量程式整天在網頁裡撈 email 位址，撈到就拿去寄廣告信。
只要信箱以完整的 `帳號@網域` 形式直接寫在網頁原始碼裡，幾乎必定會被撈走。

所以頁尾的信箱**沒有直接寫出來**，而是顯示「點一下顯示信箱」，
訪客按了才由瀏覽器組出來。我實際檢查過網頁原始碼，
**裡面找不到任何一個 email 格式的字串**。

真人看得到、按得到；只讀原始碼的爬蟲抓不到。
（會執行 JavaScript 的爬蟲仍有辦法，這種事沒有百分之百，
但這能擋掉絕大多數。）

### 隱私

頁尾只放**公司對外公開的市話 049-2896602 與公司信箱**，
沒有任何個人手機號碼 —— 照 HANDOVER 的隱私規則辦。

### 深淺色不會「閃一下」

有些網站在深色模式下打開會先閃一下白畫面。這是因為網頁是先在伺服器上做好、
再送到瀏覽器，而「這位訪客偏好深色」只有瀏覽器知道。

處理方式是：太陽與月亮兩個圖示**都畫出來**，再用 CSS 把不該出現的那個藏起來。
伺服器和瀏覽器產生的內容完全一致，就不會閃、也不會出錯。

### 圖片佔位符

現在所有照片的位置都是一塊安靜的淺色區塊，中間有一片線條茶葉，
寫著「照片準備中」。它不是暫時的權宜之計 ——
第 3 步接上真實照片後，這個元件會留下來當**後備方案**：
萬一某款茶忘了放照片、或檔名打錯，畫面顯示的還是這塊優雅的佔位符，
不會崩掉。

## 檔案放在哪裡

分成四組，不用一個一個看：

| 這一組 | 檔案 | 作用 |
|---|---|---|
| **配色** | `src/app/theme.css` | **全站所有顏色，改色只需要動這裡** |
| | `src/app/globals.css` | 基本樣式（字型、標題、焦點框） |
| **中英文** | `src/i18n/config.ts` | 支援哪些語言 |
| | `src/i18n/dictionaries/zh.json`、`en.json` | 介面上每一句話的中英對照 |
| | `src/proxy.ts` | 沒帶語言的訪客自動導到 /zh 或 /en |
| **版面零件** | `src/components/site-header.tsx` | 上方選單列 |
| | `src/components/site-footer.tsx` | 頁尾 |
| | `src/components/image-placeholder.tsx` | 圖片佔位符 |
| | `src/components/obfuscated-email.tsx` | 防爬蟲信箱 |
| | 其餘 `src/components/*` | 深淺色切換、語言切換、準備中版面 |
| **頁面** | `src/app/[locale]/page.tsx` | 首頁（版型草稿） |
| | `src/app/[locale]/teas`、`story`、`cart` | 三個「準備中」的頁 |
| | `src/app/[locale]/not-found.tsx` | 404 頁 |

> 補充：介面文字（選單、按鈕）放在翻譯檔，因為那是工程師在維護的；
> **商品的名稱與介紹不在這裡**，那些存在資料庫，第 6 步之後您能自己在後台改。

## 我在這一步修掉的兩個問題

1. **深淺色按鈕的 hydration 錯誤**：一開始用程式判斷該畫太陽還是月亮，
   結果伺服器與瀏覽器判斷不同，瀏覽器的開發者工具會跳錯誤。
   改成「兩個都畫、用 CSS 藏一個」之後就乾淨了。

2. **404 頁沒有套用網站外觀**：亂打網址時掉到 Next.js 內建的黑白畫面，
   看起來像網站壞了。加了一個「接住所有打錯網址」的機制之後，
   404 頁現在有選單、有頁尾、有配色，訪客可以直接走回去。

檢查結果：`npm run lint` 與 `npm run build` 都通過，
瀏覽器主控台沒有任何錯誤訊息，手機寬度沒有左右溢出。
