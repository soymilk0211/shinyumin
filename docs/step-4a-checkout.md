# 第 4a 步：結帳

**日期**：2026-08-17

---

## 這一步在做什麼

前面三步做完，客人可以看茶、選包裝、加入購物車 —— 但按下去只會看到
「結帳功能第 4 步開放」。**這一步就是把最後那一段路接起來：填資料、送出、訂單成立。**

第 4 步原本包含兩件事，我拆成兩半，這是前半：

| | 內容 | 狀態 |
|---|---|---|
| **第 4a 步** | 結帳表單、金額由伺服器重算、訂單寫進資料庫、完成頁 | ✅ 這一份 |
| 第 4b 步 | 訂單確認信（寄給顧客）＋ 存檔信（寄給您的 Gmail） | 下一步 |

為什麼拆開：**寄信卡在網域名稱還沒決定**。Resend 規定要先驗證自己的網域才能
寄信給客人，現在只能寄給您自己的 Gmail。與其等網域，不如先把結帳做完能用。

## ⚠️ 需要您做一件事（約 2 分鐘）

**在您做完這件事之前，結帳送出會失敗**，畫面會顯示「系統忙碌中」。

原因說明：當初建資料庫時，規格書寫的付款方式是「ATM 轉帳 + 客人回填末五碼」，
所以資料庫只認得 `atm` 這一種。後來老闆訪談的結論不一樣 ——
**匯款與貨到付款兩種，而且帳號不公開在網站上**。
資料庫還停在舊規格，得改一下才收得進新的訂單。

資料表的結構我沒辦法自己改（那需要 Dashboard 的權限），所以要麻煩您：

1. 打開 https://supabase.com/dashboard ，進入 **`shinyumin-web`**
2. 左邊選單點 **SQL Editor** → **New query**
3. 打開這個檔案，全選複製，貼進去：
   [`supabase/03-payment-methods.sql`](https://raw.githubusercontent.com/soymilk0211/shinyumin/main/supabase/03-payment-methods.sql)
4. 按 **Run**

跑完最下面會出現一行結果，寫著

```
CHECK ((payment_method = ANY (ARRAY['transfer'::text, 'cod'::text])))
```

看到 `transfer` 跟 `cod` 這兩個字就是成功了。這份 SQL 可以重複執行，
不小心跑兩次也不會壞。目前資料庫裡還沒有任何一筆訂單，改起來沒有風險。

## 客人現在會看到什麼

從購物車按「前往結帳」，會進到結帳頁。上面有：

**訂單內容**（手機在最上面，電腦在右邊會跟著捲動）
商品、包裝、數量、商品合計、運費、應付總額。
選不同的出貨方式，運費與總額會馬上跟著變。

**收件資料**
姓名、手機或電話、電子信箱、收件地址。填錯或漏填會在那一欄下面用紅字說明。

**出貨方式**（三選一，直接標出運費）

| | 運費 | 備註 |
|---|---|---|
| 黑貓宅急便 | $200 | 本島滿 $2,000 免運 |
| 郵局 | $130 | 本島滿 $2,000 免運 |
| 離島郵局 | $250 | 澎湖・金門・馬祖，**不適用免運** |

**付款方式**（二選一）：匯款／貨到付款。
底下寫著「訂單送出後我們會在兩個工作天內與您電話聯絡，確認訂單並告知匯款帳號。
為了安全，匯款帳號不會顯示在網站上。」—— 這就是您拍板的**方案 A**。
網站上沒有帳號、也沒有「回填轉帳末五碼」那一欄。

**發票**（選填）：統一編號、發票抬頭。網站只收集，發票您在外部系統開。

**備註**（選填）。

**出貨與退換貨**：把老闆訪談確認的規則寫在送出前，客人按下去之前就看得到。

送出成功之後會跳到完成頁，畫面正中央是一組**訂單編號**（例：`YM-20260817-0001`），
並告訴客人我們會在兩個工作天內來電。

## 錢是怎麼算的（這一段最重要）

一句話：**客人的瀏覽器只能告訴我們「要買哪個包裝、幾件」，錢一律由伺服器自己算。**

用比喻說：客人交給我們的是一張**購物清單**，不是一張**帳單**。
清單上寫「紅玉 150g × 2」，沒有價格；價格是我們自己回倉庫查的。

為什麼要這樣：購物車存在客人自己的手機裡，稍微懂電腦的人可以把 600 改成 1。
所以送到我們這邊的資料裡**根本沒有價格這個欄位** —— 就算對方硬塞一個進來，
我們的程式也不會讀它。

這同時解決了另一個現實問題：客人把東西放在購物車裡放了三天，
這期間您在後台調過價，結帳時算的會是**最新的價格**。

另外還有幾道防護：

- **售罄的東西送不出去。** 客人加入購物車之後那款茶售罄了，
  結帳頁會標出來、送出鈕會停用，並請他回購物車調整。
  我們不會自作主張幫他刪掉品項 —— 少寄一罐卻照收錢比較嚴重。
- **擋灌單。** 同一個人十分鐘內最多送 5 張訂單，超過就先擋下來。
  這是防有人寫程式對結帳網址連按一萬次，把資料庫塞滿假訂單。
- **訂單資料客人碰不到。** 訂單裡有姓名、電話、地址，
  這張表對訪客是完全鎖住的，只有伺服器碰得到（第 1 步做的門禁）。
- **完成頁不查資料庫。** 那一頁只把網址上的訂單編號印出來，不去查訂單內容。
  否則別人把編號一個一個試過去，就能撈走所有人的個資。

---

## 訂單編號

格式是 `YM-YYYYMMDD-NNNN`，例如 `YM-20260817-0001` ——
「2026 年 8 月 17 日的第 1 張」。日期用**台灣時間**算
（網站主機在國外，用機器時間的話台灣半夜下的單會被算成前一天）。

兩個客人同時按送出、剛好撞號的話，資料庫會擋下來，程式會自動重取號碼再試一次。

## 您可以怎麼驗證

等您跑完上面那份 SQL、而且我把這一版部署上去之後：

1. 打開 https://shinyumin.vercel.app ，隨便挑一款茶加入購物車
2. 進購物車 → **前往結帳**
3. **先故意什麼都不填按送出** —— 應該每一欄下面都跳出紅字
4. 填好資料（收件人姓名可以寫「測試」），選郵局、選匯款，送出
5. 應該跳到完成頁，看到一組訂單編號
6. 回 Supabase Dashboard → **Table Editor** → `orders`，
   應該看到剛剛那一筆，金額是 **商品合計 + 運費**
7. 點 `order_items`，應該看到品項與**下單當下的價格**

順便可以測兩件事：

- 把出貨方式改成**離島郵局**，運費應該變 $250，而且**加到超過 $2,000 也不會免運**
- 選**黑貓**、買到超過 $2,000，運費應該變成「免運」

測試訂單可以在 Table Editor 裡直接刪掉（先刪 `order_items` 再刪 `orders`）。

## 有三件事想請您確認

1. **「拆封時錄影」這句話的措辭。**
   老闆說破損理賠需要客人拆封時錄影，我在結帳頁寫成：

   > 商品若有破損可退款退貨。請您在拆封時錄影，作為破損理賠的依據。

   這句話會被每一位客人看到，用字要不要調整請您決定。

2. **多久沒付款就取消訂單？** 訪談時這一題留白了。
   現在的訂單送出後狀態是「待付款」，會一直留著。
   等第 6 步做後台時，您可以手動改成「已取消」，所以不急，但想先問一下。

3. **貨到付款要不要加收手續費？** 黑貓與郵局的代收貨款通常會收一筆。
   目前程式**沒有加收**，貨到付款與匯款的運費一模一樣。要加的話再告訴我。
