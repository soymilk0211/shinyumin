# 第 0 步：建立專案骨架

**完成日期**：2026-08-16

---

## 這一步做了什麼

用一個比喻：這一步等於是**在空地上打好地基、接上水電，還沒有蓋任何一面牆**。

網站現在可以在您的電腦上跑起來，但畫面還是 Next.js 的預設歡迎頁 ——
還沒有茶、沒有購物車、沒有任何御茗的內容。那些是後面幾步的事。

具體做了三件事：

1. **建立 Next.js 專案**：安裝了網站的骨架程式（Next.js 16 + TypeScript + Tailwind CSS）。
2. **接上 GitHub**：程式碼已經備份到 `https://github.com/soymilk0211/shinyumin`。
   以後每一步做完都會自動上傳，等於是「有版本紀錄的雲端備份」——
   萬一改壞了，隨時可以退回任何一個過去的版本。
3. **寫好 `CONTEXT.md`**：這份文件定義了整個專案的**共同語言**。

---

## 關於 `CONTEXT.md`（這一步最重要的產出）

蓋房子之前要先確定「客廳」「陽台」指的是哪裡，不然工班會做錯。
`CONTEXT.md` 就是這份約定。

裡面最關鍵的一組區分是「**商品**」與「**規格**」：

- **商品**＝一款茶，例如「紅玉紅茶」。它有故事、有風味描述、有照片。
- **規格**＝一款茶的一種包裝，例如「紅玉 150g 真空罐裝」。

**只有規格能被放進購物車。** 因為「我要買紅玉」這句話還沒講完 ——
沒說是哪一種包裝。價格、售罄與否，都是掛在規格上，不是掛在商品上。

這個設計的好處是：**未來要賣禮盒時，禮盒只是多一個規格，不用改架構。**

## 檔案放在哪裡

| 檔案／資料夾 | 是什麼 |
|---|---|
| `CONTEXT.md` | **專案共同語言**（這一步的主要產出，建議您讀一下） |
| `README.md` | 專案的第一頁說明，告訴接手的人先讀哪份文件 |
| `docs/HANDOVER.md` | 之前六輪訪談的完整結論 |
| `docs/step-0-setup.md` | 就是您正在讀的這份 |
| `src/app/` | 網站的頁面程式碼會住在這裡（目前只有預設首頁） |
| `public/` | 圖片、商標之類的檔案會放這裡 |
| `package.json` | 記錄這個專案用到哪些工具 |
| `node_modules/` | 自動下載的工具程式（很大，**不會**上傳到 GitHub，也不需要備份） |

## 您可以怎麼驗證

### 方法一：在自己電腦上打開網站

打開終端機，切到專案資料夾，執行：

```bash
npm run dev
```

然後用瀏覽器打開 http://localhost:3000

**預期會看到**：Next.js 的黑白預設歡迎頁（有一個 Next.js 的商標）。
看到這個畫面就代表地基是好的。

要關掉的話，在終端機按 `Ctrl + C`。

### 方法二：上 GitHub 看

打開 https://github.com/soymilk0211/shinyumin

**預期會看到**：專案的檔案列表，以及頁面下方自動顯示的 `README.md` 內容。
點進 `CONTEXT.md` 可以直接在網頁上閱讀。
